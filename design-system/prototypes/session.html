Project-scoped model profile defaults

Allow a project to specialize model selection without copying the full provider configuration or hiding invalid references.

Problem

Every project currently inherits all three global profiles. A full configuration copy would drift and make validation ambiguous.

Acceptance criteria

  • Override principal, deep, or fast independently.
  • Missing keys inherit the matching global profile.
  • Unknown models and variants fail before work starts.
  • The resolved profile is recorded on each Execution.

Model profile defaults per project

Goal and background

Allow one project to override only the model profiles it needs while retaining the validated global configuration as the baseline.

Scope and non-goals

  • Add a strict partial project profile map.
  • Keep provider configuration global and unchanged.
  • Do not introduce fallback for unknown models or variants.

Ordered implementation

  1. Schema boundary. Define the partial override in config/schema.ts and reject unknown keys.
  2. Project resolution. Merge the partial map before Session admission while preserving global defaults.
  3. Verification. Cover partial overrides, invalid references, and unchanged global behavior.

Acceptance and validation

  • Each profile can be overridden independently.
  • Missing profiles resolve to the matching global selection.
  • Invalid model or variant references fail before work starts.
